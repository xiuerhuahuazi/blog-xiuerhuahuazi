Skills over MCP is now in public beta in Claude, so MCP servers can ship skills alongside their tools. We're also giving servers ways to handle longer, more interactive work with Claude: Tasks and Elicitation are now generally available, and File Uploads is rolling out soon.

Skills over MCP 现在已在 Claude 里进入公测，也就是说 MCP 服务器可以把技能和工具一起发出来1。我们同时让服务器能与 Claude 一起处理更耗时、更具交互性的工作：任务（Tasks）和征求确认（Elicitation）现已正式可用，文件上传（File Uploads）也即将推出。

Two years ago, Anthropic launched the Model Context Protocol (MCP) as a new standard for connecting AI agents to the systems where data lives. The spec has kept evolving to meet the connectivity needs of agents in production, and is becoming foundational for agentic messaging and orchestration.

两年前，Anthropic 发布了模型上下文协议（MCP），把它作为一项新标准，用来把 AI 智能体连接到数据所在的系统。这份规范一直在演进，以满足生产环境中智能体的连接需求，并正在成为智能体之间的消息传递与编排的基础2。

With today's updates, Claude can work with a server more like it works with another agent: learning from it, delegating to it, and exchanging input and files along the way.

有了今天这些更新，Claude 跟一个服务器协作的方式，会更像它跟另一个智能体协作：向它学习、把任务委派给它，并在过程中互相交换输入和文件3。

01

Ship expertise alongside tools with Skills over MCP随工具一起交付「怎么做」：Skills over MCP

本节要点

工具的名字和描述只说得清「能做什么」，说不清「该怎么用」。Skills over MCP 让服务器把技能跟工具一起发布：按需加载，随服务器更新，用户没有额外要装的东西。Shopify、HubSpot、Atlassian 已经在用，Carta 即将推出。

Tool names and descriptions tell Claude what a server can do, but don't cover how to handle specific use cases. With Skills over MCP, servers can publish skills alongside their tools to help Claude take on longer, multi-step work. Claude loads a skill only when it's needed, keeping context use low. Skills update with the server, so developers can ship tools and guidance together and users have nothing separate to install.

工具的名字和描述告诉 Claude 这个服务器能做什么，但说不清具体场景该怎么处理。有了 Skills over MCP，服务器可以把技能跟工具一起发布，帮 Claude 承担更长的多步工作。Claude 只在需要时才加载技能，这样占用的上下文很少。技能随服务器一起更新，于是开发者可以把工具和说明一起交付，用户也不用再单独安装什么。

Skills can cover best practices, step-by-step workflows, or even playbooks tailored to a user's account or organization. Using Skills over MCP:

技能可以是最佳实践、分步骤的工作流，甚至可以是针对某个用户账户或某个组织专门定制的操作手册。在实际使用中，用上 Skills over MCP 的几家是这样：

  • Shopify helps Claude design and update a merchant's online store end to end.
  • HubSpot onboards customers and gets them set up in Claude.
  • Atlassian helps Claude draw on deep organizational context for insights and work analysis.
  • Carta will help Claude draft and issue equity from an uploaded document (coming soon).
  • Shopify 帮 Claude 端到端地设计和更新商家的线上店铺。
  • HubSpot 帮客户完成上手引导，并在 Claude 里把他们配置好。
  • Atlassian 让 Claude 能借助对组织内部的深入了解，来做洞察和工作分析。
  • Carta 将让 Claude 基于上传的文档起草并发放股权（即将推出）。

Skills over MCP is in public beta in Claude and Claude Code, on by default for Pro, Max, and Ultra plans and available to Team plans once an admin enables it. Coming soon to Enterprise.

Skills over MCP 在 Claude 和 Claude Code 里都是公测状态：Pro、Max、Ultra 套餐默认开启，Team 套餐要管理员打开后才能用4。Enterprise（企业版）即将跟进。

02

MCP servers can now take on long-running, interactive work with ClaudeMCP 服务器现在能在 Claude 里承担长时、可交互的工作

本节要点

以前工具调用必须当场跑完，Claude 才能往下走。现在有两条路：Tasks 把长活变成可轮询的后台任务；Elicitation 让服务器中途停下来问用户。第三条 File Uploads（文件直达服务器、不经过上下文窗口）即将推出。

Agents in production are taking on longer, more consequential jobs. Servers can now support that work by running it in the background, checking in with users, and receiving files from Claude.

生产环境里的智能体，正在承担更长、后果也更重的活儿。服务器现在可以从三个方面支撑这类工作：把活儿放到后台执行、与用户沟通并征询意见、以及从 Claude 那里接收文件。

Hand off long-running work with Tasks. Tool calls used to have to finish before Claude could move on. With Tasks, servers can run operations that take time, or even full agent loops, while Claude keeps working and picks up the result when it's ready. Using Tasks, ZoomInfo runs deeper accounts and contact research that previously took several prompts.

把长时工作交出去，用 任务（Tasks）5。以前工具调用必须跑完，Claude 才能继续往下做。有了任务，服务器可以跑那些耗时的操作，甚至跑完整的智能体循环；与此同时 Claude 继续干自己的活，等结果好了再来取。ZoomInfo 用任务来做更深入的目标客户公司（accounts）与联系人调研——这种活儿以前要好几轮提示词才做得下来。

Ask for input mid-call with Elicitation. Some actions need a user's sign-off, like spending money or deleting data. With Elicitation, a server can pause to ask the user for input through a form or link, then continue where it left off. Using Elicitation:

调用到一半需要输入，就用 征求确认（Elicitation）。有些操作需要用户签字点头，比如花钱，或者删数据。有了征求确认，服务器可以中途停下来，通过表单或链接向用户要输入，然后从停下之处接着继续6。用上征求确认的几家是这样：

  • Supabase confirms costs before creating a paid project and before running destructive SQL.
  • Railway asks before making potentially destructive changes, like removing a service.
  • GitHub has users enter a repository's name before an agent deletes it.
  • Supabase 在创建付费项目之前、在运行破坏性 SQL 之前，都会先确认费用。
  • Railway 在做可能造成破坏的改动（比如删掉一个服务）之前，会先问一句。
  • GitHub 会在智能体删除某个仓库之前，让用户先把仓库名输一遍。

Tasks and Elicitation are now generally available in Claude and Claude Code for Pro, Max, and Ultra plans, and rolling out to Team and Enterprise organizations.

任务和征求确认现在在 Claude 与 Claude Code 里对 Pro、Max、Ultra 套餐正式可用，并正在向 Team 与 Enterprise（企业版）组织逐步开放。

Send and receive files with File Uploads. Claude will be able to pass files to MCP servers, not just text. The File Uploads extension sends PDFs, spreadsheets, and images to a server without passing them through the context window.

收发文件，用 文件上传（File Uploads）。Claude 将能把文件传给 MCP 服务器，而不只是文本。文件上传（File Uploads）这个扩展会把 PDF、电子表格和图片发给服务器，而不必让它们经过上下文窗口7。

File Uploads is rolling out soon in Claude and Claude Code to Pro, Max, Ultra, and eligible Team and Enterprise plans.

文件上传即将在 Claude 和 Claude Code 里向 Pro、Max、Ultra 以及符合条件的 Team 与 Enterprise（企业版）套餐推出。

04

Built on stronger foundations for connecting agents in production为生产环境的智能体连接，打更结实的地基

本节要点

过去一年 MCP 在 Claude 里变好用的四件事：工具定义按需加载（多服务器场景能省 85% 以上的上下文）、规范改成无状态、企业托管授权、MCP Apps 带来完整界面。规模上，每月 SDK 下载量已超 7 亿次、连接器过万。

Thanks to contributions from across the AI ecosystem, MCP now sees over 700 million monthly SDK downloads, and there are over 10,000 MCP connectors for Claude. We've worked with the MCP community to improve how MCP works in Claude. Over the past year, it has become:

靠着整个 AI 生态的贡献，MCP 现在每月的 SDK 下载量超过 7 亿次，Claude 这边也已经有 10,000 多个 MCP 连接器。我们跟 MCP 社区一起，改进了 MCP 在 Claude 里的工作方式。过去一年里，它变成了这样：

  • More token efficient: Tool search loads tool definitions only when needed, which can cut the context they use by over 85% in multi-server setups.
  • Easier to scale: The latest MCP spec is stateless and supported across Claude products, making it easier to build servers and maintain their reliability as they grow.
  • Simpler to authorize: The Enterprise Managed Auth extension lets admins authorize supported servers once, so users connect automatically.
  • More interactive: The MCP Apps extension brings full interfaces into Claude, beside the conversation or full screen.
  • 更省 token：工具检索（tool search）只在需要时才加载工具定义；在多服务器配置下，这能把工具定义占用的上下文削减 85% 以上。
  • 更容易扩展：最新的 MCP 规范是无状态的，并且在 Claude 各产品上都得到支持，这让构建服务器、以及随规模增长维持其可靠性都更容易。
  • 授权更简单：企业托管授权（Enterprise Managed Auth）这个扩展让管理员一次性授权支持的服务器，用户端就能自动连上。
  • 更有交互：MCP Apps 扩展能把完整界面搬进 Claude——可以贴在对话旁边，也可以全屏打开。

Together, these improvements make MCP easier to build on and adopt, and give the standard a strong base to continue evolving for the needs of agents in production.

合在一起，这些改进让 MCP 更容易在其上搭建、也更容易被采用，也让这个标准有了一个结实的地基，可以继续朝着生产环境中智能体的需求演进。

Skills 扩展规范（MCP）

modelcontextprotocol.io · Skills — Model Context Protocol

正文对应：Skills over MCP

这是什么：Skills 扩展的正式规范页：服务器怎么对外暴露技能、客户端怎么发现和读取。

为什么值得点：本文第 1 节说的「按需加载」「随服务器更新」，在这页都能对上具体的协议消息，不是营销话术。

不点开也能拿到的重点

扩展名 io.modelcontextprotocol/skills，对应的 SEP-2640 已经是 Final 状态。服务器必须同时声明 resources 能力和这个扩展，并实现 skills/list 与 skills/get；技能文件本身走 resources/read 读取。一个技能是含 SKILL.md 的目录，遵循 Agent Skills 规范，可以带附属文件；清单里每个文件都带 SHA-256 摘要和字节数，供客户端校验。

  • 只读 resources/read 不会激活技能——要由宿主走「加载技能」的路径，校验并（视需要）取得用户批准后才进模型上下文
  • 支持分页（nextCursor），列表结果要求 resultType: complete
  • ttlMs 与 cacheScope 控制缓存新鲜度和共享范围

Tasks 扩展规范（MCP）

modelcontextprotocol.io · Tasks — Model Context Protocol

正文对应：任务（Tasks）

这是什么：Tasks 扩展的规范页：长请求怎么变成可轮询的任务、状态怎么走。

为什么值得点：本文第 2 节的第一项能力。这页解释了「为什么不用直接把连接挂住」——那是理解 Tasks 的关键一问。

不点开也能拿到的重点

服务器判断某个请求会很久时，先回一个任务句柄（resultType: task，含 taskId、初始状态、TTL、建议轮询间隔），而不是阻塞等结果。状态有 working、input_required、completed、failed、cancelled；客户端用 tasks/get 轮询，任务要输入时通过 tasks/update 交回去，也可以 tasks/cancel——取消是协作式的，服务器不保证立刻停。

  • 能力协商：客户端带 io.modelcontextprotocol/tasks，服务器在 server/discover 里声明
  • 四个好处：不需要长连接、客户端崩溃能续、进度可见、可中途交互
  • 任务在响应发出之前就已经落库，断线重连还能用同一个 ID 继续

Elicitation 规范（MCP 2026-07-28）

modelcontextprotocol.io · Elicitation — Model Context Protocol

正文对应：征求确认（Elicitation）

这是什么：征求确认的正式规范：两种模式、能力声明、以及哪些信息绝不能走表单。

为什么值得点：本文只用一句话带过「通过表单或链接」。链接二字背后其实是两套模式，安全边界也不同，看这页才知道差别在哪。

不点开也能拿到的重点

服务器可以在处理请求途中向用户要信息，分两种模式：form 模式用服务器给的 JSON schema 渲染表单；URL 模式跳到外部链接，用于必须在客户端之外完成的敏感交互。规范明确禁止用 form 模式索要密码、API key、访问令牌、支付凭据，这类必须走 URL 模式。客户端要声明 elicitation 能力，空对象等于只支持 form。

  • 服务器不得用客户端没声明的模式发请求
  • 客户端必须让用户看清是哪个服务器在要信息，并能拒绝、取消
  • URL 模式：跳转前要显示目标域名并取得同意

术语表

正文里带虚线底线的词，悬停即出解释；这里是完整 14 条，可当速查用。

Model Context Protocol模型上下文协议（MCP）

Anthropic 2024 年开源的连接标准：用一套统一协议把 AI 客户端和外部系统（数据仓、代码仓、CRM 等）接起来，任何厂商都能实现。

相当于智能体世界的 USB 接口。

MCP serverMCP 服务器

按 MCP 协议对外提供能力的一方：一个进程或远程服务，能提供工具、资源，现在还能提供技能。

就是插在 USB 口上的那台设备。

agent智能体（agent）

能自己多步行动的系统：读任务、调工具、看结果、再决定下一步，而不是一问一答。

像会自己找工具的实习生。

spec规范（spec）

MCP 的正式文本：规定消息格式、能力协商、各扩展的必须与可选行为，是实现和兼容性的依据。

像插座标准，插头能不能插看它。

public beta公测（public beta）

功能已对所有用户开放，但接口和行为还可能调整；与 GA（正式可用、承诺稳定）相对。

能用了，但还会改。

skills技能（skills）

写给模型看的操作说明，通常是一个含 SKILL.md 的目录，可以带附属文件；只在需要时加载。

相当于随设备附赠的操作手册。

Tasks任务（Tasks）

MCP 的异步执行机制：服务器先返回 taskId 和状态，客户端轮询，跑完再取结果，不必一直占着连接。

像取餐号：先给你号，好了再取。

Elicitation征求确认（Elicitation）

服务器在调用途中向用户要信息或确认的机制：可以弹表单（form 模式），也可以跳到外部链接（URL 模式）。

像付款前的确认弹窗。

File Uploads文件上传（File Uploads）

MCP 扩展：客户端把 PDF、电子表格、图片等文件直接交给服务器，而不是把内容塞进对话上下文。

像递 U 盘，而不是把文件念一遍。

extension扩展（extension）

在 MCP 基础协议之外加的一层可选能力：双方都声明支持才启用，不支持就退回基础协议。

像协议上的可选配件。

context window上下文窗口（context window）

模型一次能看到的全部内容上限（对话、工具定义、文件内容都算）；塞得越满，留给干活的空间越少。

像一张固定大小的书桌。

tool search工具检索（tool search）

先只把工具索引给模型，需要时再按需加载工具定义，避免几十个服务器的定义把上下文撑满。

像先看目录，再取书。

stateless无状态（stateless）

每个请求自带所需信息，服务器不依赖上一次请求留下的会话；扩容、重连、部署到 serverless 都更容易。

像每次进门都重新报一遍身份。

connector连接器（connector）

Claude 目录里对 MCP 服务器的产品化叫法：一键连上某个服务，背后是一个 MCP 服务器或插件。

同一个东西，售卖页上的名字。

译者注

正文中上标数字对应这里，解释的是「直译会看不懂」或「原文本身含糊」的地方。

01

Skills over MCP 是功能名

这里说的是一个具体功能：一套让 MCP 服务器把「技能」（含 SKILL.md 的说明目录）随工具一起发布的扩展。不是泛指「MCP 有很多技巧」。

02

agentic messaging and orchestration

这两个词还没有稳定的中文定名。这里的含义是：智能体之间互相发消息、以及把多个智能体组织起来干活——MCP 正在成为这类协作的通用接口。

03

这句话是全文的框架

「更像跟另一个智能体协作」是这批更新的主线：服务器不再是一个被动函数库，而是一个能学、能派活、能交换输入和文件的合作方。后面三项能力都在给这句话补细节。

04

套餐名保持原文

套餐名保留英文原名，首次出现时括注中文，以免与实际计费页面对不上。本节说的是 Skills over MCP 的开放范围：Pro、Max、Ultra 默认开启，Team 要管理员打开，Enterprise 尚未开放。

05

Tasks 不是待办事项

MCP 规范里的 Task 是一次异步执行的句柄：服务器先返回 taskId 和状态，客户端轮询，跑完了再取结果。跟产品界面里的「待办任务」不是一回事。

表单 / 链接对应两种模式

规范里分 form 模式（服务器给 JSON 表单，客户端渲染）和 URL 模式（跳到外部链接处理，密码、支付凭据这类敏感信息不允许走 form 模式经过客户端）。

07

为什么强调「不经过上下文窗口」

文件按字节直达服务器，模型不必先「读一遍」再复述，因此不占上下文、也不受上下文长度限制；这也是它能传 PDF、表格、图片的前提。
