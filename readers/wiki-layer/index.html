传统做法：每次上传，每次重读

  1. 把几十份文件塞给模型，每次提问都重新读一遍
  2. 词元花在重复阅读上，问得越多越贵
  3. 文件之间没有链接，关联靠模型当场猜
  4. 文件之间的关联容易漏，答案质量不稳定
  5. 没有积累：这次懂了，下次从头来

  1. LLM 一次性清洗、结构化、互链成 Markdown

三个文件夹就是全部：raw/ 是不可改的原料，wiki/ 是 LLM 自己维护的 Markdown 知识库，第三样是规则——清洗方式、模板、链接、元数据。注意原文的编号从 2 开始（见译注 N3）。

The entire system is built around three core folders:

整套系统围绕三个核心文件夹搭建：

  • raw/ - immutable source files
  • raw/——不可改动的原始文件

This is where all original materials are stored: HTML pages, PDFs, text notes, screenshots, spreadsheets, and any other raw data

所有原始材料都放这儿：HTML 页面、PDF、文字笔记、截图、表格，以及任何其他原始数据。

This folder is never edited manually, it remains the single source of truth

这个文件夹从不手动改动，它始终是唯一的事实来源。

2. wiki/ - the main knowledge base

2. wiki/——主知识库3

Clean, well-structured Markdown files generated and maintained by the LLM itself

由 LLM 自己生成并维护的、干净且结构良好的 Markdown 文件。

This becomes the primary workspace the model interacts with going forward

从此以后，这就是模型主要打交道的工作区。

3. Instructions and templates

3. 指令与模板

Separate files that define all the rules:

单独的文件，用来定下所有规则：

How data should be cleaned, which templates to use, how links are created, what metadata should be added, and how the knowledge base should be updated over time

数据该怎么清洗、用哪些模板、链接怎么建、要加哪些元数据，以及知识库该怎样随时间更新。

Step-by-Step Guide to Building a Wiki Layer搭一个 Wiki 层的四步

本节要点

四步：建项目 → 在 Claude 里跑一个「结构化智能体」把 raw/ 编译成 wiki/ → 用 Obsidian 打开看知识图谱 → 以后直接说「用 wiki/ 里的库」。原文没有给提示词全文，只给了它该做什么。

1. Set Up the Project

1. 建好项目

Create a root project folder and place all your existing materials inside a raw/ subfolder

建一个项目根文件夹，把你现有的材料全部放进里面的 raw/ 子文件夹。

2. Launch the Structuring Agent

2. 启动「结构化智能体」

In Claude (or any powerful LLM with file and code support), provide a dedicated system prompt

在 Claude（或任何支持文件与代码的强模型）里，给它一段专用的系统提示词。

The agent will automatically:

这个智能体会自动：

  • clean files from technical junk, ads, and unnecessary formatting
  • convert everything into clean, readable Markdown
  • apply predefined templates
  • create internal wiki links ([[Page_Name]])
  • add metadata and establish relationships between documents
  • 清掉文件里的技术性杂物（残留代码、乱码等）、广告和多余的格式
  • 把所有东西转成干净、可读的 Markdown
  • 套用预先定好的模板
  • 建立内部的 Wiki 链接（[[Page_Name]]）
  • 补上元数据，并在文档之间建立关联

3. Open the Knowledge Base in Obsidian

3. 用 Obsidian 打开知识库

Simply open the project folder in Obsidian

在 Obsidian 里直接打开项目文件夹就行。

You’ll instantly get:

你会立刻得到：

  • a visual knowledge graph with automatic links
  • powerful full-text search
  • the ability to jump between connected notes in seconds
  • 一张带自动链接的可视化知识图谱
  • 强大的全文搜索
  • 可以几秒钟就在互相关联的笔记之间跳来跳去

4. Work With the Finished Knowledge Base

4. 用这套搭好的知识库干活

Now, instead of uploading dozens of files every time, you simply tell the model:

现在，你不用每次上传几十个文件了，只要跟模型说：

“Work with my Wiki database inside the wiki/ folder”

「用我 wiki/ 文件夹里的知识库来干活」

The LLM can then instantly retrieve information from a clean, structured, and interconnected knowledge system

LLM 就能立刻从一个干净、有结构、互相连通的知识系统里取信息。

Why a Wiki Layer Is Better Than the Traditional Approach为什么 Wiki 层比传统做法好

本节要点

作者列了五条好处：省词元、更准、可扩展、工作流更好、隐私。其中「隐私」那条要打问号——流程里用云端 Claude 编译时，原始文件其实是要上传的（见译注 N4）。

  • token efficiency - the model no longer has to repeatedly re-read raw files every time you ask a question
  • higher accuracy - all information is already cleaned, structured, and interconnected
  • scalability - the knowledge base can easily grow to hundreds or even thousands of documents
  • better workflow - obsidian turns the entire system into a visual “second brain”
  • privacy - everything stays on your local machine, nothing needs to be uploaded to the cloud
  • 词元效率——你每次提问，模型都不必再反复重读原始文件
  • 更高的准确度——所有信息都已经清洗、结构化、互链好了
  • 可扩展性——知识库能轻松长到几百甚至几千份文档
  • 更好的工作流——Obsidian 把整套系统变成一个可视化的「第二大脑」
  • 隐私——一切都留在你的本机，什么都不用上传到云端。4

术语表

正文里带虚线底线的词，悬停即出解释；这里是完整 14 条，可当速查用。

large language models大语言模型

ChatGPT 背后那类 AI 模型：读过海量文字，回答时一个词一个词往下接。本文要解决的，就是它每次都得把材料重读一遍的问题。

像一个读过很多书、但每次只能看几页的助手。

tokens词元

词元是模型读写的计量单位：它把文字切成小片段，一个片段算一个词元，收费和长度上限都按它算。本文节省的就是它。

像按条计费的短信，只不过它数的不是字，而是词元。

context上下文

上下文指模型这一次能看到的全部内容：你的问题、上传的文件、前面聊过的记录都算。文件一多就装不下、彼此接不上，本文用整理好的知识库来缓解。

像一张一次只能摊开这么大的桌面，文件越多越摊不开。

knowledge base知识库

知识库是事先整理好、按规则归档的资料集合，模型直接在里面查，不必每次重读原始文件。本文里它就是那个 wiki/ 文件夹。

像把散落资料分类上架之后的图书馆。

Wiki LayerWiki 层

Wiki 层是原始文件和模型之间的一层整理结果：模型先把材料清洗、结构化、互相链接，之后只在这一层工作，不再反复读原始文件。

像把一堆原书重新编成一套带索引的百科。

raw files原始文件

原始文件指你手头未经处理的材料：网页、PDF、文字笔记、截图、表格等。本文把它们放进 raw/ 文件夹，不手动修改，作为唯一可信来源。

像做菜前买回来、还没洗切的原材料。

MarkdownMarkdown

Markdown 是一种用纯文本写格式的简单标记法：用符号表示标题、列表、加粗，文件小、人和程序都好读。本文让模型把所有材料都转成它。

像用记事本就能写出标题和列表的简易排版法。

ObsidianObsidian

Obsidian 是本地笔记软件：打开文件夹就能读里面的 Markdown，并按链接画成网络图。本文用它把 wiki/ 变成可点可搜的界面。

knowledge graph知识图谱

知识图谱是把笔记间的链接画成一张网络图：每篇笔记是一个点，链接是连接的线。本文靠它一眼看出哪些主题连在一起，由 Obsidian 显示。

像地铁线路图：站点是笔记，线路是它们之间的链接。

system prompt系统提示词

系统提示词是开工前一次性交代给模型的角色和规则，比如怎么清洗、用哪个模板、加哪些字段。它和每次提问分开，本文靠它约束结构化智能体。

像新员工入职时拿到的那份岗位说明书。

agent智能体

智能体是能自己连做多步的 AI：不只回一句话，还会读文件、改文件、按规则批量处理。本文的「结构化智能体」负责把 raw/ 转成 wiki/。

像一个照清单办事的实习生，不用你每步都盯着。

metadata元数据

元数据是描述一篇笔记本身的信息，比如日期、作者、标签、摘要，不是正文。本文让模型给每篇 wiki 笔记统一加上这些字段，方便筛选和互相引用。

像书脊上的标签：不读内容也知道是哪本书。

second brain第二大脑

第二大脑指把外部资料系统化存起来、随时可查的个人知识库，等于给记忆配一个外挂仓库。本文用它形容 Obsidian 里那张可视化知识网络。

像给大脑配了一块可随时检索的外接硬盘。

wiki linksWiki 链接

Wiki 链接是笔记之间用双方括号写的内部链接，形如 [[Page_Name]]，点一下即可跳转。本文让模型生成这类链接，把笔记连成一张网。

像文档里可以点击跳转的「参见」超链接。

译者注

正文中上标数字对应这里，解释的是「直译会看不懂」或「原文本身含糊」的地方。

01

「Karpathy 的 Wiki 层」到底出自哪里

原文只给了括号里的 (LLM Wiki)，没有链接。它对应 Andrej Karpathy 2026 年 4 月公开的 LLM Wiki 构想（GitHub gist 与他的 X 帖「LLM Knowledge Bases」）：raw/ 放原始资料、LLM 增量编译成 markdown wiki、用 schema 约束、定期 lint。三处差别值得知道：① gist 没有把「Wiki Layer」当专名（它写的是「There are three layers」「The LLM owns this layer entirely」），这个名字是本文作者起的；② gist 与本文都是「先编译一次、之后持续维护」，差别在 gist 把 ingest / query / lint 写成日常操作，本文只用一句「随时间更新」带过；③ 本文也没提 gist 里的 index.md / log.md。文末「延伸阅读」第 1 条就是出处。

02

标题的 90% 与正文的 70–90%

标题取了上限「Save 90%」，正文写的是「up to 70-90% on repeated queries」——两者不是两个数。真正的问题是：标题只取上限，而且 70–90% 怎么测出来的没交代（哪种查询、多长的文档、和什么基线比）。另外，Karpathy 的 gist 里「90%」「percent」「token」的命中数都是 0——这个百分比出自本文作者，不是 Karpathy 的量测。两处都按原文照录、不做统一；建议把它当成「量级上的省」，不要当成精确指标。

03

原文的编号从「2.」开始

原文列三个文件夹：raw/（这一条是项目符号，没有编号）、「2. wiki/」、「3. Instructions and templates」——「1.」不存在。这是原文的排版瑕疵，不是漏译；本页按原样保留，并在这里备案。

04

「什么都不用上传云端」是有条件的

这一条只能理解为查询阶段：知识库在你本机，提问时不用再把原始文件传上去（原文并没有明说这个限定）。但第 2 步「在 Claude 里跑结构化智能体」本身就要把 raw/ 的内容交给云端模型处理。想全程不出本机，得换成可本地运行的模型——原文没有交代这一层，不要把它读成「这个方案天然隐私安全」。
