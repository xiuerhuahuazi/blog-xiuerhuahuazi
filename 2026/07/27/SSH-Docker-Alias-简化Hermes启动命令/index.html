SSH 连接 Docker 容器太麻烦？一招用 alias 把命令缩短到 5 个字符

一条 alias 把「ssh 进 NAS + docker exec + 进容器」缩成 5 个字符。

每次 SSH 进 NAS，再 sudo docker exec -it hermes-hermes-1 hermes chat 一长串，是不是很烦？

本文记录一下我怎么把这个命令从 50 多个字符缩短到 hermes 五个字符，一次配置，永久生效。

我的情况

  • 设备：绿联 NAS（DXP4800PLUS-120）
  • 部署：Hermes Agent 跑在 Docker 容器里，容器名是 hermes-hermes-1
  • 习惯：用 SSH 从外网连进 NAS，偶尔进容器跟 AI 助手对话

每次都要敲：

sudo docker exec -it hermes-hermes-1 hermes chat

打错一个字符就废，重输一遍更烦。

原理：Linux shell alias

alias 是 bash/zsh 自带的「命令别名」机制，作用就是把一长串命令映射成一个短名字。每次 shell 启动时读 ~/.bashrc，里面的 alias 自动生效。

格式就一行：

alias 短名='长命令'

配置方法

打开 NAS 上你用户的 ~/.bashrc，在文件末尾加两行：

alias hermes='sudo docker exec -it hermes-hermes-1 hermes chat'
alias h='sudo docker exec -it hermes-hermes-1 hermes chat'

保存退出。然后让当前 SSH 会话立即生效（不用断开重连）：

source ~/.bashrc

之后在任何 SSH 窗口里直接敲 hermes 或更短的 h，就自动执行那串完整命令。

下次新开 SSH 也会自动加载，不需要重复操作。

几个细节

1. 为什么不用 sudo 也能省？

如果你 NAS 的 SSH 用户本身就在 docker 组里（sudo usermod -aG docker 用户名），连 sudo 都可以省掉。我留 sudo 是因为我没动这个，安全一点，多敲 5 个字符无所谓。

2. 普通登录 SSH 会自动加载 ~/.bashrc 吗？

会的。bash 作为交互式登录 shell 启动时，会读 ~/.bash_profile / ~/.bash_profile / ~/.profile，而这些文件通常又会 source ~/.bashrc。配置一次就够了。

3. 容器名换了怎么办？

只改那一行 alias 就行：

alias hermes='sudo docker exec -it 新容器名 hermes chat'

4. 想管理多个容器？

可以再加几条：

alias dps='sudo docker ps --format "table {{.Names}}	{{.Status}}	{{.Ports}}"'
alias dlogs='sudo docker logs -f --tail 100'
alias dexec='sudo docker exec -it'

比如 dps 看运行中的容器，dlogs hermes-hermes-1 看 hermes 的日志，dexec hermes-hermes-1 /bin/bash 进容器 shell。

5. 影响范围

只改你自己 home 目录下的 .bashrc，不影响其他用户，不影响 Docker 服务，不影响容器本身。改错了删掉那两行就恢复，没有任何副作用。

一个坑（我踩过）

Hermes 这个 AI 自己如果是在 Docker 容器里跑的，它写文件是写到容器内的 /opt/data/home，不是宿主机 NAS 的 /home/你的用户名/。所以如果让 AI 帮你配置 alias，它可能写到错的地方，你以为没生效，其实是路径不对。手动敲那两条 echo 命令最稳。

小结

  • alias 是 Linux shell 自带功能，零依赖
  • 只改 ~/.bashrc，影响范围可控
  • 一次配置，永久生效
  • 配错了删一行就恢复

省下来的不是字符，是每次进 AI 对话时那一秒烦躁。
