原理：Linux shell alias

alias 是 bash/zsh 自带的「命令别名」机制，作用就是把一长串命令映射成一个短名字。每次 shell 启动时读 ~/.bashrc，里面的 alias 自动生效。

几个细节

1. 为什么不用 sudo 也能省？

如果你 NAS 的 SSH 用户本身就在 docker 组里（sudo usermod -aG docker 用户名），连 sudo 都可以省掉。我留 sudo 是因为我没动这个，安全一点，多敲 5 个字符无所谓。

2. 普通登录 SSH 会自动加载 ~/.bashrc 吗？

会的。bash 作为交互式登录 shell 启动时，会读 ~/.bash_profile / ~/.bash_profile / ~/.profile，而这些文件通常又会 source ~/.bashrc。配置一次就够了。

5. 影响范围

只改你自己 home 目录下的 .bashrc，不影响其他用户，不影响 Docker 服务，不影响容器本身。改错了删掉那两行就恢复，没有任何副作用。

一个坑（我踩过）

Hermes 这个 AI 自己如果是在 Docker 容器里跑的，它写文件是写到容器内的 /opt/data/home，不是宿主机 NAS 的 /home/你的用户名/。所以如果让 AI 帮你配置 alias，它可能写到错的地方，你以为没生效，其实是路径不对。手动敲那两条 echo 命令最稳。

小结

  • alias 是 Linux shell 自带功能，零依赖
  • 只改 ~/.bashrc，影响范围可控
  • 一次配置，永久生效
  • 配错了删一行就恢复

省下来的不是字符，是每次进 AI 对话时那一秒烦躁。
